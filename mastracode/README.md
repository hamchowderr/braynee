# Braynee — Mastra Code adapter

The [Mastra Code](https://code.mastra.ai/) surface for braynee. The Claude Code surface lives at
the repo root (`.claude-plugin/`); both read the **same** `skills/` and `scripts/`, so the two
hosts cannot drift apart.

## Install

```bash
mastracode
/plugins        # Install new plugin -> Local path -> C:/Users/HamCh/code/braynee
```

Point it at the **repo root**, not this folder. That is deliberate — see below.

## Why the manifest is at the repo root

`.mastracode-plugin.json` lives one level up, so Mastra Code treats the whole repo as the plugin
root. Mastra Code discovers a plugin's skills at `<pluginRoot>/skills`, which is already
braynee's real skills directory — so the 23 skills are shared with the Claude Code surface with
no copies, no symlinks, and no build step.

Two directories are easy to confuse:

| | value | used for |
|---|---|---|
| plugin root | `<repo>` | `skills/`, `commands/` discovery |
| `ctx.pluginDir` | `<repo>/mastracode/src` | `path.dirname(entryPath)` — **not** the root |

`src/index.ts` resolves the repo root back out of `ctx.pluginDir` with `../..`.

## What this adapter provides

- **Skills** — all 23, straight from `<repo>/skills`.
- **Instructions** — the vault search mandate, generated by
  `scripts/lib/vault-instructions.mjs`, the same module the Claude Code
  `UserPromptSubmit` hook uses. Output is byte-identical between the two hosts.

Instructions carry that text here because **Mastra Code cannot inject context from hooks** — the
SDK computes a hook's `additionalContext` but the TUI never reads it (verified against 0.32.4).
Hooks on this host can only run side effects, warn, or block.

Paths in the generated instructions are always **absolute and resolved at load time**. Never emit
a `${CLAUDE_PLUGIN_ROOT}`-style placeholder: Claude Code expands that token, no other host does,
and an unexpanded placeholder reaches the agent as literal text.

## Local development

```bash
npm install          # devDeps only (typescript, @types/node)
npx tsc --noEmit     # typecheck
```

`mastracode/plugin` is a **peer** dependency. Mastra Code links the installed `mastracode`
package into `node_modules/` automatically whenever it loads or installs the plugin. Note that
running `npm install` here removes that link — re-run Mastra Code (or re-create the link) before
typechecking, otherwise `tsc` reports `Cannot find module 'mastracode/plugin'`.

## Not yet ported

- **Hooks** — still configured by hand in `~/.mastracode/hooks.json`; plugins cannot contribute
  hooks. Tracked in `cp-3o3g.3`, which also retires the interim translation shim.
- **Agents** — braynee's `agents/*.md` have no declarative analog; Mastra Code has three fixed
  subagent types (`explore`/`plan`/`execute`). They will become plugin tools declaring
  `render: { type: 'subagent' }`. Tracked in `cp-3o3g.4`.
