# Look back and research again

You won't catch everything the first time, and the world keeps moving. Something
you built yourself last month may now exist as an official feature or a
well-maintained open project.

## Steps

1. **List what was built in-house**: custom code, scripts, workarounds,
   hand-written integrations. Note what each does and what it costs to keep.
2. **Search again for each** (see `find-the-foundation` and `read-every-source`):
   new official features, new open-source projects, new official libraries.
3. **Compare honestly** in a table: what ours does, what theirs does, gaps both
   ways, maintenance, licence, cost, effort to switch.
4. **Recommend one** per item: keep ours, switch, or combine (theirs as the main
   path, ours as a fallback).
5. If switching, plan it so nothing breaks: run both side by side, move over,
   then retire the old one.

## Rules

- Don't defend the old work because it was effort. Judge it on today's facts.
- Don't switch for novelty; switch when it's clearly better or cheaper to keep.
